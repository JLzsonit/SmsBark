01

为什么不是「一个 App」

先说清楚这件事的边界，省得你白折腾

!

iOS 没有任何公开 API 能让 App 读取短信收件箱。 短信数据库在系统沙盒里，App Store 审核也明确禁止这类行为（隐私 + 反垃圾短信是硬红线）。 市面上所谓的"iOS 短信转发"，全部是走「快捷指令自动化」这条系统级通道，没有例外。 你真正要做的，是把这条路配好。

环节由谁负责说明
接收短信iOS 系统系统短信 App 收到即触发
监听触发快捷指令「收到信息」自动化按发件人 / 关键词过滤
拦截判定快捷指令「匹配文本」+「如果」命中关键词直接终止，不发出请求
推送出去Bark（或任意 HTTP 接口）一条 GET 请求即可
落地到设备Bark App / 自建服务iPhone、iPad、Mac 同时响

在快捷指令里搭出来

        
按顺序点，第 4 步的拦截是可选的

      

    


    

      

        
1

        

          
新建空白自动化

          
打开「快捷指令」App，切到底部「自动化」标签，点右上角 ＋，在触发器列表里选 「信息」（旧版本叫「收到信息」）。

          
快捷指令 → 自动化 → ＋ → 信息

        

      


      

        
2

        

          
设置过滤条件

          

            「发件人」留空 = 任何人发来的都转发；填了号码/邮箱就只转发那个人。
            「信息包含」可填关键词做二次筛选，比如只关心含「账单」「验证码」的短信。
            多个条件下方切到「满足任意条件」。
          

          
关键：下方「运行前询问」一定要关掉，否则每来一条短信都要手动点一下「运行」。

        

      


      

        
3

        

          
添加「获取快捷指令输入的详细信息」

          
添加这个动作，把属性设为 「发件人」。再添加一次，属性设为 「内容」。这两个就是短信的发件人和正文。

          
如果属性列表里没有「内容」，直接用「快捷指令输入」本身代替即可。

        

      


      

        
4

        

          
（可选）插入关键词拦截

          
想屏蔽营销短信就加这一步：用「匹配文本」跑一下上一节生成的正则，命中就「停止此快捷指令」。停止指令执行后，后面的推送动作不会跑，另一台 iPhone 也就收不到这条。

          
匹配文本  →  如果 [匹配结果] 有任何值  →  停止此快捷指令

          
位置很关键：必须在「获取 URL 内容」之前。放在后面等于短信已经推出去了才判断，白忙。

        

      


      

        
5

        

          
「文本」→「URL 编码」→「文本」

          
照上面生成器里的 ①②③ 三步操作：先把正文拼成文本，URL 编码，再拼进推送链接。

          
动作 1  文本：发件人：[发件人变量]
             [内容变量]

动作 2  URL 编码：[上一步的文本]

动作 3  文本：https://api.day.app/KEY/📩新短信/[URL编码结果]?group=…

        

      


      

        
6

        

          
「获取 URL 内容」

          
方法选 GET，URL 填上一步的文本变量。就这样，不需要任何解析、不需要正则。

          
点右下角运行测试一次，手机应该立刻收到一条推送。收到就成功了。

        

      

    

  


  
  

    

      05
      

        
这些坑提前知道

        
社区里踩得最多的几条

      

    

    

      

        只转发新短信，历史短信不会补发
        
自动化是「事件触发」——只有在规则建好之后收到的短信才会推送。想补历史只能手动导出。

      

      

        开了「过滤未知发件人」可能收不到推送
        
如果短信设置里开了「过滤未知发件人」，被拦截到「未知发件人」列表的信息，自动化通常不会触发。做转发的话建议关掉这个开关。

      

      

        iMessage 也会触发
        
触发器监听的是「信息」App 收到消息这件事，iMessage 和普通 SMS 都会触发。只想转发 SMS 的话，可以在条件里按发件人筛选，或在正文里判断是否含「【」等特征词。

      

      

        必须有网络，且 URL 有长度上限
        
短信刚到的时候如果没网，这次推送就丢了（短信本身在手机上）。另外超长短信（多条拼接的长文本）会让 URL 超长，部分服务器会拒收——这种情况改用 POST 方式，或在文本动作里截取前 N 个字符。

      

      

        耗电和延迟
        
这是系统级自动化，不常驻后台，几乎不耗电。延迟一般在 1 秒内，偶尔在网络切换时会有几秒。

      

      

        想推到飞书 / 钉钉 / 企业微信 / Telegram
        
把第 6 步的 URL 换成对应机器人的 Webhook 就行，前面的文本拼装逻辑完全一样。Bark 只是最省事的一种。

      

      

        关键词填了但没拦住，一般是这三个原因
        

          一是全角半角：短信里常出现 ＴＤ（全角），你填的是 TD（半角），匹配不上，两个都加上。
          二是短信被拆成多条：超长短信会分片到达，关键词可能正好落在第 2 片，而每一片都会独立触发一次自动化。
          三是关键词本身带空格或标点，实际短信里没有。
          排查方法：把这条短信原样粘到第 03 节的测试框里，判定结果是「会推送」就说明词没对上。
        

      

      

        拦截了，但我想留个记录怎么办
        

          把「停止此快捷指令」换成「获取 URL 内容」，推送到另一个分组（比如 group=已拦截、level=passive），
          这样它只安静躺进 Bark 的通知中心，不会有横幅和声音，事后还能翻。
          完全不留痕就保持「停止」不动——请求根本不会发出，服务端零记录。
        

      

      

        自动化里本来就有「信息包含」，为什么还要单独做拦截
        

          自动化那个条件只支持单个关键词，而且是「必须包含」的白名单语义——你没法写「包含 A 但不包含 B」。
          要做黑名单、多关键词、任意命中，只能靠「匹配文本」+「如果」自己判断。
