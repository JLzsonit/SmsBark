# SmsBark 项目详细介绍

> 一句话：**SmsBark 是「一台 iPhone 收短信 → 另一台 iPhone 立刻收到」这套快捷指令方案的操作客户端。**
> 收到短信这件事由 iOS 系统与「快捷指令」完成；SmsBark 负责把这条链路配置好、把规则算准、把请求发对、把每一环的结果记下来。

---

## 一、它到底解决什么问题

### 典型场景

| 场景 | 痛点 | SmsBark 的做法 |
| --- | --- | --- |
| 主力机放家里/办公室，随身带备用机 | 验证码、银行扣款、快递通知全落在没带的手机上 | 短信一到，另一台立刻弹横幅，并可按级别穿透专注模式 |
| 一张卡专门收验证码，装在旧 iPhone 上 | 每次都要跑去拿那台手机 | 旧机自动转发，新机直接看，还能自动复制正文 |
| 双机双卡，工作号与生活号分开 | 不想被营销短信轰炸 | 黑名单关键词直接掐掉，连请求都不发出去 |
| 需要留一份短信台账 | 手动抄、截图、发微信都很麻烦 | Bark 历史记录 + App 内「运行记录」双份留痕 |

### 这个问题的本质

iPhone 上的短信在系统沙盒里，**任何第三方 App 都读不到收件箱**，App Store 审核也明确禁止这类能力。所以「iOS 短信转发」只有一条合法且稳定的通道：

```
iOS 系统收到短信
      ↓
快捷指令「收到信息」自动化（系统级事件触发）
      ↓
调用一个 App 提供的动作（App Intents）
      ↓
发一条 HTTP GET 到 Bark
      ↓
另一台 iPhone 的 Bark 客户端弹通知
```

SmsBark 就是这条链路上**唯一需要安装的那个 App**——它把中间三步（配置、判定、请求）全部收进一个原生界面里，让用户不用在快捷指令里手拼十来个动作。

---

## 二、它在链路里扮演的角色

SmsBark 不是服务端，也不参与投递。它做的是四件"旁边的事"：

| 角色 | 具体含义 |
| --- | --- |
| **配置中心** | 服务器地址、Device Key、标题、分组、中断级别、提示音、图标、跳转地址、正文模板，全部可视化编辑，实时预览拼好的链接 |
| **规则引擎** | 黑名单 / 白名单双模式的关键词判定，在动作执行时**本地**生效，命中就直接不发请求 |
| **日志台** | 动作每跑一次写一条记录：收到什么、判了什么、HTTP 结果如何——用来定位"明明加了关键词却还是收到" |
| **自测工具** | 一键测试推送验证 Key 与网络；粘贴一条短信实时看会不会被拦；生成给手动拼动作方案用的正则 |

**关键设计取舍**：真正的判定发生在**快捷指令调用 App 动作的那一刻**，而不是在 App 界面里。所以 App 不需要后台常驻、不需要常开，配置改完立刻对下一次短信生效。

## 三、界面：四个页签

### 1. 概览（HomeView）

打开 App 的第一屏，"这条链路现在通不通"一眼可见。

- **最近一次动作**：最新一条运行记录，带颜色状态（绿=已推送 / 橙=已拦截 / 红=失败或跳过）、相对时间、收到的发件人与正文片段。一条记录都没有时，直接提示去查三件事：自动化开关、触发器小圆点、「运行前询问」。
- **当前配置**：就绪状态胶囊 + 服务器、Device Key（掩码显示为 `abcd••••wxyz`）、分组、中断级别。
- **验证链路**：发送一条真实测试推送；或复制拼好的完整链接，发到别的设备上点开验证。
- **拦截规则摘要**：当前是黑名单还是白名单生效、有多少个关键词。
- **它是怎么跑起来的**：四步链路图解。
- **边界说明**：明确写出"iOS 不允许读短信，收到短信那一刻由快捷指令接管"，避免用户误解 App 能力。

### 2. 推送（ConfigView）

所有 Bark 侧参数都在这里。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 服务器地址 | `https://api.day.app` | 支持自建 Bark，结尾斜杠会自动去掉 |
| Device Key | 空 | 在 Bark App 首页复制，只存本机 |
| 通知标题 | `📩 新短信` | 会做 URL 路径段编码 |
| 分组 | `短信` | Bark 列表里按此归类 |
| 中断级别 | 时效性通知 | 普通 / 时效性（可穿透专注模式）/ 静默 / 重要警告 |
| 提示音 | bell | bell、birdsong、electronic、horn、glass、synth 或不指定 |
| 重复响铃 | 0 次 | 0–5，对应 `call` 参数 |
| 通知图标 | 空 | 传 URL |
| 点击跳转 | 空 | 可填 `shortcuts://` 回到快捷指令 |
| 正文模板 | `发件人：{{发件人}}\n{{内容}}` | 支持 `{{发件人}}` `{{内容}}` `{{时间}}` |
| 保存到 Bark 历史 | 开 | `isArchive=1` |
| 自动复制正文 | 关 | `autoCopy=1`，适合抄验证码 |

页面底部实时显示**拼好的完整推送链接**，带示例正文，可直接复制验证。

### 3. 拦截（RulesView）

规则引擎的控制台。

- **模式**：黑名单（命中就拦）/ 白名单（只放行命中）。
- **关键词**：逐条增删、去重、忽略大小写；三套常用词库一键套用——营销广告词（20 个，含"退订/TD/优惠/秒杀/免息"等）、运营商推广（9 个）、验证码/账单（10 个，套用时会自动切到白名单语义）。
- **拦截后留痕**（可选）：被拦下的短信也推一条 `level=passive`、无提示音的静默通知到指定分组（默认「已拦截」），只进通知中心，事后可翻。
- **正则输出**：给"不用本 App 动作、手动拼动作"的老方案用，关键词里的正则符号会自动转义。
- **试一下**：粘贴一条短信，实时显示"已拦截 / 会推送"以及命中的是哪个词。
- **运行记录**：最近 12 条（本地保留 80 条），五种结果——已推送 / 已拦截 / 拦截·留痕 / 失败 / 跳过；可刷新、可整段复制、可清空。

### 4. 指引（GuideView）

给第一次用的人一条最短路径。

- 「一键创建自动化」按钮：深链 `shortcuts://create-automation` 直接跳到新建自动化页。文档里如实说明苹果没有开放"替用户创建自动化"的接口，触发器和动作无法由 App 预填。
- **四步实机路径**（按 iOS 27 界面文案逐字对齐）：
  1. 自动化 → ＋ → 选「通知」→「我收到来自 信息」
  2. 添加操作 → 搜「SmsBark」→ 选「转发短信到 Bark」
  3. 点「发件人」/「短信内容」→ 面板里点「快捷指令输入」→ 轻点「输入快捷指令的信息」→ 类型选「通知」→「获取」里分别选「发件人」和「正文」
  4. 关掉「运行前询问」→ 完成
- 第 3 步单独做成高亮子清单，因为这是全流程唯一容易接错的地方。
- **容易踩的坑**：别开「过滤未知发件人」、只转发新短信、iMessage 也会触发、必须有网络、分片长短信。
- **FAQ**：为什么不能全自动建、拦了却还是响怎么查、参数里出现「输入快捷指令的信息」正不正常、能不能推到飞书/钉钉/企业微信、换机后要改什么。

## 四、核心机制

### 4.1 唯一的对外接口：`转发短信到 Bark`

App 通过 App Intents 向快捷指令暴露一个动作，两个参数：

| 参数 | 类型 | 默认 | 接到哪个变量 |
| --- | --- | --- | --- |
| 发件人 | 字符串 | 空 | 「快捷指令输入 → 输入快捷指令的信息 → 类型：通知 → 获取：发件人」 |
| 短信内容 | 字符串 | 空 | 同上，最后「获取」选「正文」 |

执行时 `openAppWhenRun = false`，完全在后台跑，不把 App 拉到前台。

### 4.2 一次执行的完整流程

```
读取本机 PushConfig
   ├─ 没有 Device Key → 记「跳过」并返回提示
   ↓
参数清洗 + 自愈
   ├─ 发件人里含换行或超过 60 字 → 判定为正文塞错了位置，挪到内容里
   ├─ 内容为空但发件人有字 → 判定两个参数接反了，长的当正文
   ↓
读取本机 RuleConfig
   ├─ 规则未启用（关键词为空）→ 直接放行
   ├─ 黑名单命中 → 拦
   ├─ 白名单未命中 → 拦
   ↓
被拦？
   ├─ 开了留痕 → 推一条 passive 静默通知到「已拦截」分组 → 记「拦截·留痕」
   └─ 没开留痕 → 什么都不发 → 记「已拦截」
   ↓
放行 → 按模板拼正文 → 拼 URL → GET（超时 15s）
   ├─ Bark 返回 code=200 → 记「已推送」
   ├─ 返回其它 code → 记「失败」并带上 Bark 的错误信息
   └─ 网络异常 → 记「失败」
```

**参数自愈**是这套方案里很实用的一层兜底：快捷指令里接变量是最容易出错的一步，用户常把整条通知塞进「发件人」、或把两个参数接反。自愈逻辑让"接错但还能跑通"成为可能，而不是静默失败。

### 4.3 关键词判定规则

- **匹配方式**：纯子串包含（`contains`），不做分词、不做模糊。
- **归一化**：先把全角转半角（`ＴＤ` → `TD`），再删掉所有空白字符，避免短信里插空格把关键词拆断。可选忽略大小写（只对英文有意义）。
- **判定对象**：只判短信正文，不判发件人。
- **结果**：黑名单命中 = 拦；白名单未命中 = 拦；规则为空 = 全放行。
- **正则派生**：同一批关键词会生成 `(?:词1|词2|...)` 形式的正则（可加 `(?i)` 前缀），供手动拼动作的方案粘进「匹配文本」动作，符号已自动转义。

### 4.4 推送链接的拼法

采用 Bark 的路径式接口，而不是 JSON POST：

```
{server}/{deviceKey}/{title}/{body}?group=…&level=…&sound=…&call=…&icon=…&url=…&isArchive=1&autoCopy=1
```

- `title` 与 `body` 作为**独立路径段**严格 percent-encode（只保留字母数字与 `-._~`），所以中文、换行、斜杠都不会把 URL 拆断。
- 空值参数一律不拼，避免生成 `group=&sound=` 这类空串。
- 之所以不用 POST JSON：短信正文里出现英文引号或反斜杠会让 JSON 解析失败，推送直接丢；URL 编码没有这个问题。

### 4.5 数据存在哪

全部在本机 `UserDefaults`，三个 key：

| Key | 内容 |
| --- | --- |
| `smsbark.push.v1` | `PushConfig` 的 JSON |
| `smsbark.rules.v1` | `RuleConfig` 的 JSON |
| `smsbark.runlog.v1` | `RunLogEntry` 数组，最多 80 条，新的在前 |

写入走 `didSet` + 后台队列编码，避免逐字输入时卡主线程。App Intent 在非视图环境直接读同一份 JSON，所以规则改了立刻对下一次短信生效，不需要两边同步。

### 装机

产物是**未签名 IPA**，不能双击安装，需要自签：

- **Sideloadly / AltStore**（Windows 可用）：免费 Apple ID 签名，7 天有效，到期重签；
- **TrollStore**：支持的系统可永久安装；
- 有付费开发者账号可签一年，或用 Xcode / Apple Configurator。

## 六、技术栈与实现要点

| 层 | 实现 |
| --- | --- |
| UI | 纯 SwiftUI，无第三方依赖；卡片式布局，四个 `NavigationStack` 包在 `TabView` 里 |

| 文案 | 全中文硬编码，无本地化文件 |
| 测试 | 无单元测试，靠 App 内自测与运行记录手工验证 |

## 七、隐私与安全

- 不收集任何数据，**没有服务端**，无统计、无埋点、无第三方 SDK。
- Device Key 与全部规则只写本机 `UserDefaults`。
- 唯一的网络请求是发往用户自己配置的 Bark 地址。
- 允许 HTTP 明文（`NSAllowsArbitraryLoads`），是为了让自建 Bark 用 `http://` 也能跑；如果用官方 HTTPS 地址，这条并不被用到。
- 未签名 IPA 自签安装，证书与信任链由用户自己的 Apple ID 管理。

## 八、已知边界

这些是设计上的硬限制，不是缺陷：

1. **只能转发"建好自动化之后"收到的短信**，历史短信不会补发。
2. **必须有网络**，短信到达那一刻没网，这次推送就丢了（短信本身还在手机上）。
3. **超长短信会分片到达**，每片独立触发一次；关键词恰好落在另一片时可能判不出来。
4. **iMessage 也会触发**，只想转 SMS 需在自动化条件里按发件人筛选。
5. **开了「过滤未知发件人」会漏**，被归到「未知发件人」的信息通常不触发自动化。
6. **规则只判正文**，不判发件人；按发件人过滤要放在自动化触发器里。
7. **URL 有长度上限**，超长短信可能被服务端拒收。
8. **自签有效期 7 天**，到期需重签（付费账号可一年）。

## 九、故障排查速查表

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 概览页「还从没执行过」 | 自动化没调到动作 | 查自动化开关是否绿色、触发器小圆点是否绿色、「运行前询问」是否关闭 |
| 记录里"内容为空" | 自动化里「短信内容」参数没接到「获取 → 正文」 | 回指引页第 3 步重接，参数框只用「选择变量」，别用键盘打字 |
| 记录里"已推送"但该拦的没拦 | 关键词和原文没对上（全角/空格/分片） | 把原文粘进「拦截 → 试一下」复核，必要时补全角写法 |
| Bark 返回非 200 | Device Key 错误、服务器地址错、自建 Bark 异常 | 用「测试推送」单独验证，看返回的 `message` |
| 推送成功但另一台没响 | 专注模式、通知权限、Bark 客户端被静音 | 中断级别改「时效性通知」，检查 Bark 通知权限 |
| 拦截生效但想留档 | 未开「拦截后留痕」 | 拦截页打开开关，填分组名（默认「已拦截」） |
| 换手机后推送失败 | 重装 Bark 导致 Device Key 变化 | 在新 Bark 里复制 Key，更新「推送」页 |

## 十、与安卓侧的关系

同目录下的 `../SmsForwarder` 是安卓侧的短信转发与拦截 App（基于 SmsForwarder 二次开发）。两边解决同一个需求，路径完全不同：

- **安卓**能直接读短信收件箱、能常驻后台、能监听广播，所以 App 自己就是完整链路。
- **iOS**只能借快捷指令，所以 SmsBark 的定位是"客户端 + 规则引擎 + 日志台"，收短信那一步永远在系统手里。

## 十一、术语

| 术语 | 含义 |
| --- | --- |
| Bark | 一款开源 iOS 推送工具，通过一条 HTTP GET 就能给自己的设备推通知 |
| Device Key | Bark 为每台设备生成的密钥，出现在推送 URL 里 |
| 中断级别 | iOS 通知的打扰等级：普通 / 时效性 / 静默 / 重要警告 |
| 自动化 | 快捷指令里"某事件发生时自动运行某流程"的功能，本方案靠「收到信息」触发 |
| App Intent | iOS 提供给系统与快捷指令调用的 App 动作接口，本方案的「转发短信到 Bark」就是一个 |
| 留痕 | 被拦截的短信仍推一条静默通知，只进通知中心、不响铃 |
